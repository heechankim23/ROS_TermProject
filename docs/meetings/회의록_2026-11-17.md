### 2-1. 코드로 확인한 원인 (병합 관리)

| 문제 | 원인 | 근거 | 확실도 |
|---|---|---|---|
| 1. 6·7번 재시도 없이 즉시 실패 | 빈 접근 지점을 못 찾으면 예전에는 직선 offset 지점(`standoff_point`)으로 대신 갔다. C 가 이 대체 동작을 지웠고, 접근 지점이 없으면 **재시도 루프 안에서 바로 abort** 한다 (`max_retries` 를 쓰지 않음) | `nav_bridge.py` 204~206행, 251~252행 | 코드로 확인 |
| 2. 주차구역 A `no path` | 정적 지도만으로는 길이 있다 (`check_env.py` 맵 점검에서 "구역 A: 충전소에서 1 m" OK). 실행 중 라이다로 본 킥보드(60초 기억)와 새 대각선 통과 금지가 겹쳐 좁은 틈이 막힌 것으로 추정 | `planner.py` 대각선 검사, 시뮬 재현 필요 | 추정 |
| 3. 메시지가 원인을 구분 못함 | `make_goal()` 이 "현재 위치 없음"과 "빈 자리 없음" 모두 `None` 을 돌려줘서 메시지 하나로 합쳐짐 | `nav_bridge.py` 237~253행 | 코드로 확인 |

C 에게 제안할 수정 방향 (결정은 C):

## 부록. 테스트 명령어 (Ubuntu, ROS 2 Humble)

새 터미널마다 워크스페이스에서 `source /opt/ros/humble/setup.bash` 와 `source install/setup.bash` 를 먼저 한다.
시나리오는 한 번에 하나만 실행하고, 끝나면 Ctrl+C.

### 최신 main 받기·빌드
```bash
git checkout main && git pull origin main
```
```bash
colcon build --symlink-install && source install/setup.bash
```

### 단위 테스트
```bash
cd src/kickboard_robot && python3 -m pytest -q test/ ; cd ../..
```

### kinematic (Gazebo 없이 로직만)
```bash
ros2 launch kickboard_sim bringup.launch.py sim:=kinematic scenario:=s1_single rviz:=true
```
```bash
ros2 launch kickboard_sim bringup.launch.py sim:=kinematic scenario:=s5_aging rviz:=true
```
```bash
ros2 launch kickboard_sim bringup.launch.py sim:=kinematic scenario:=s8_auto_cancel
```

### Gazebo
```bash
ros2 launch kickboard_sim bringup.launch.py scenario:=s1_single
```
```bash
ros2 launch kickboard_sim bringup.launch.py scenario:=s1_single gui:=false rviz:=true
```

### 예전 main(`ef0b0ca`)과 s5 비교 (2장 확인 필요 항목)

```bash

```
```bash

```
