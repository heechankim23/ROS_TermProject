새 분담: 코드는 E, 문서는 모두

남은 코드는 대부분 "합치고, 돌려 보고, 고치는" 일이라 한 사람이 쥐는 편이 빠릅니다. 문서는 그 부분을 만든 사람이 검토해야 정확하고, 그 과정이 곧 질의응답 준비가 됩니다.

굴러가기 위한 전제

  1. 11-26(목) 코드 넘김. 각자 로컬 작업을 모두 push. 이후 main에 코드를 넣는 사람은 E 한 명이고, 다른 사람 파일을 E가 고치면 담당자가 하루 안에 확인합니다. README 9장 규칙도 이렇게 바꿉니다.
  2. E의 코드 범위를 줄입니다. 새 기능보다 회귀가 모두 통과하고 데모가 매번 같은 결과로 끝나는 것이 우선입니다.
  3. 문서는 하나의 목차로. E가 목차와 용어표를 먼저 깔고, 각자 자기 장을 채웁니다.

도킹은 애니메이션

dock_controller 노드와 DockToCharger 액션은 그대로 두고, 안쪽만 "정해진 경로로 몇 초 동안 도크까지 옮기고 성공 반환"으로 바꿉니다. mission_manager와 launch는 건드리지 않습니다.

문서에는 태그 기반 정밀 도킹의 설계안을 적고, 시연은 애니메이션이라고 밝힙니다. 회귀 기대값에서 도킹 실패 경로는 뺍니다.

  • k00 요청 재전송, k16 제한 110분
  • 도로 s1~s19 + 경북대 k00~k32 전체 회귀
가능하면시간이 남으면
  • 출발 전 요청 "충전 중이면 취소"

보류문서에 "향후 확장"으로만
  • 충전 이상 감지, 움직이는 장애물 구분
  • Nav2, 실제 카메라 + AprilTag
  • 여러 대 운영
