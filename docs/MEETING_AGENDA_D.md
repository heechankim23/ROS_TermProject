## 1. 하역공간을 "인증된 사람만 쓰는 스테이션"으로 바꿀지

**배경 (실측)**
- 지금 하역은 두 종류다. 공개 주차구역(세운 킥보드는 다시 정상 킥보드가 되어 학생이 타고 감)과 충전소 충전 자리 4칸.
- 주차구역은 구역 안이 비어 있어도 못 내리는 경우가 있다. 로봇은 구역 밖 정해진 위치에 서야 팔(약 1.2 m)이 닿는다.
  - s5 kinematic (리팩터링 후 실행): 정렬에 실패해 구역 밖에 쓰러진 채 남은 킥보드가 A 의 서는 위치에서 0.83 m.
    A* 가 8 s x 3회 경로를 못 찾고(약 27 s 손실), 주차구역에 세울 4대를 전부 충전소에 내렸다. A 의 자리 4개는 비어 있었다.
- 실제 맵에서 서는 위치는 변 8개 중 2개만 쓸 수 있고(벽 여유 1.05 m), 자리는 구역마다 4개다.
- 다른 사람이 세운 킥보드는 미션이 모른다. GPS 오차(시뮬 σ 1 m)가 자리 간격(0.45 m)보다 커서 GPS 로는 알 수 없다.

**제안**: 하역공간을 칸이 정해진 스테이션으로 하고, 인증된 사람만 쓰게 한다. 스테이션이 칸별 점유·충전 여부를 알려 준다.
- 없어지는 문제: 다른 사람이 세운 킥보드, 자리 반납 추측, 팔이 닿는 자리 계산.
- 남는 문제: 스테이션 앞 접근 통로가 막히는 경우 -> 다른 스테이션으로 (D 가 구현).

**정할 것**
- 주차구역과 충전소를 스테이션 하나로 합칠지 (배터리 낮은 킥보드는 충전 칸 우선).
- s1·s9 통과 기준 변경 (E), 스테이션 배치와 주변에 킥보드가 생성되지 않게 하는 시나리오 규칙 (A),
  스테이션 상태 인터페이스 예: `/station_status` (E), 스테이션 정밀 접안 (C).

## 5. 하역 위치가 막혔을 때 목표를 다시 고르는 일 (C)

- 하역 위치는 `GoToPose(standoff=0)` 로 보낸다. nav_bridge 는 standoff > 0 일 때만 근처 빈 자리를 다시 고른다.
- 하역에도 "막히면 근처 빈 자리"를 지원하면 미션 쪽 여유 거리를 줄일 수 있다.
- 그전까지 D 는 이동 피드백의 `attempt` 를 보고 일찍 취소한 뒤 다음 후보로 넘기는 방식으로 대응할 수 있다.

## 6. 이동 실패를 "나중에 다시"로 돌리기 (B)

- 지금: 수거 중 이동 실패는 바로 NEEDS_HUMAN (사람 호출). 캠퍼스에서는 사람이 몰리는 등 잠깐 막히는 일이 흔해서
  사람 호출이 남발될 수 있다.
- 미션이 REQUEUE 로 돌려놓을 수는 있지만, 대기열 `select` 는 점수 최고 WAITING 항목을 바로 다시 고른다
  (REQUEUE 는 대기 시간을 유지해서 점수가 높다). `SelectNextTarget` 요청에는 로봇 위치만 있어 미션이 "이건 잠시 빼 줘"를 말할 수 없다.
- 제안: 대기열이 `nav_failures` 가 늘어난 항목을 일정 시간(예: 60 s, 코스트맵 장애물 기억 시간) 선택에서 빼고,
  N 회(예: 3)를 넘으면 NEEDS_HUMAN. 대기열(B)에서 구현하면 인터페이스 변경 없이 된다. 미션(D)은 이동 실패를 REQUEUE 로 보고.
