## 1. 하역공간을 "인증된 사람만 쓰는 스테이션"으로 바꿀지

## 10. 새 시나리오 제안 (11-24, 회귀·정렬 시험에서 나온 것)

시나리오 파일은 A 담당(경북대는 `build_knu_scenarios.py`)이라 제안으로 전달. "예상"은 지금 role_D 코드 기준 예측이며 아직 돌려 보지 않음.

**10-1. 기본 수거·하역 (도로판, A·D)**
- 인도 진입 금지 쪽 킥보드: 인도 깊숙이 있어 로봇은 차도에만 설 수 있음 -> 차도 가장자리 1.15~1.6 m 자리에서 팔을 뻗어 수거. 예상 통과 (자리 채점 단위 테스트로만 확인).
- 팔은 닿는데 차체가 못 들어감: 거치대 사이 좁은 틈 -> 차체 겹침 검사로 다른 각도 자리 선택. 예상 통과.

**10-2. 주행·장애물 — 정렬 자리 (도로판, A·C·D)**
- 킥보드 바로 옆 나무(로봇 쪽 0.75 m): 나무를 피한 각도에서 수거. 예상 통과 (예전 방식은 실패). 무작위 시험에서 확인한 배치를 정식 시나리오로.
- 정렬 자리에 사람이 25~40 s 서 있음: 지금은 20 s 뒤 align_failed + 관리자 알림. 사람 호출보다 "다른 대상 먼저, 나중에 다시"(6장)가 맞는지 정할 것.
- 라이다 범위 밖(경북대 3.5 m) 지도에 없는 적치물이 정렬 자리에: 도착해서 보이면 다음 후보로. 예상 통과, 다만 주행 재시도만큼 느려짐.

**10-3. 한 킥보드에서 정렬을 너무 오래 시도함 (D)**
- 지금 최악: 시도 1번당 `align_timeout_sec` 90 s x (1 + `align_retries` 2) + 기다림 5 s + 후보 없을 때 20 s -> 한 대에 약 5 분.
  그동안 시간 소모(k2)만으로 도로판 약 6 %, 경북대 약 3 % 를 쓰고 다른 요청은 밀린다.
- 제안: 정렬 전체 시간 상한(예: 60~90 s)을 두고, 넘으면 실패 대신 REQUEUE("나중에 다시", 6장)로 돌려 다른 대상을 먼저 처리.
- 시나리오: 정렬 자리가 계속 반쯤 막혀 재시도가 길어지는 배치 + 로봇 배터리 낮게 시작.

**10-4. 충전 칸에 꽂혀 있는데 배터리가 안 오름 (A·B·D, 꼭 추가)**
- 충전 모듈 고장, 접점 이물질 등으로 스탠드 고장 이벤트 없이 충전이 안 되는 경우. 지금은 k22 처럼 `stand_fault` 이벤트가 있어야만 안다.
- 더 나쁜 점: 펌웨어는 충전 칸(role charge)에 있는 킥보드는 배터리 부족 요청을 보내지 않음 -> 충전이 안 되는 칸에서 조용히 방전된다.
- 제안: 충전 칸 + 일정 시간(예: 10 분) 배터리가 오르지 않거나 내려감 -> "충전 이상" 관리자 알림, 그 칸을 고장으로 빼고 킥보드를 다른 충전 칸으로 옮기는 요청.
- 시나리오: k22 변형 — 고장 이벤트 없이 C 칸 하나가 충전을 못 함.

**10-5. 배터리 부족 신고인데 현장에서는 충전 중 (B, 복합 판단)**
- 신고(또는 대기 중 요청) 사유는 배터리 부족, 그사이 사용자가 충전 칸에 꽂아 배터리가 오르는 중 -> 배터리 상승으로 확인하고 취소.
- 지금 자동 취소 조건이 "배터리 20 % 이상"이라 계속 수거 대상 -> 예상 실패 (9-2 의 충전 중 신호로 해결).

**10-6. 정렬 중 보행자 무리 (D 돌발상황, D)**
- k28(수업 교대 혼잡) + 보행자 경로가 정렬 자리 위를 지남 -> 1 초마다 다시 채점하며 기다렸다 수거. 예상 통과.
- 다듬을 점: 지금은 최근 1.5 s 라이다를 모두 장애물로 보므로 계속 지나가는 무리는 "고정 장애물"과 구분이 안 되고 20 s 뒤 실패할 수 있다.
  움직이는 점(여러 스캔에서 자리가 바뀌는 점)과 고정 점을 나눠, 움직이는 것만 막고 있으면 더 기다리도록.

**10-7. 충전 바꿔치기 (D 돌발상황, A·B)**
- 리워드를 위해 완충(또는 덜 찬) 킥보드를 빼고 자기가 타고 온 킥보드를 꽂음.
- 배터리 감시로 잡을 수 있는 것: "대여 없이 충전이 끊김"(충전 중이던 킥보드의 배터리가 멈추거나 내려감) 직후 "방금 주행을 끝낸 킥보드가 같은 구역에서 충전 시작".
  두 사건이 짧은 시간 안에 같은 구역에서 나면 바꿔치기 의심으로 관리자 기록.
- 어느 칸인지까지는 따지지 않는다: 킥보드가 무거워 멀리 못 옮기므로, GPS 로 주차 가능한 구역 안에 있으면 충분 (칸 id 필드 추가 불필요).
- 빠진 킥보드가 구역 밖이면 기존 "구역 밖" 요청으로 수거됨.

**제외한 것**
- 충전이 도중에 끊김(30 % 에서 대여 없이 빠짐): 20 % 아래로 내려가면 펌웨어가 배터리 부족 요청을 다시 보내고, 20 % 위에서는 탈 수 있으므로 서비스 문제 없음.
  단 충전 칸에 그대로 있으면 요청이 안 나가므로 10-4 에서 다룸.
- 넘어졌는데 충전 중: 넘어진 채로는 충전할 수 없으므로 성립하지 않음.
