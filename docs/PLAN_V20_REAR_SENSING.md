# v20 수정 계획: 후방 인식 확보

작성일 2026-11-27 (같은 날 기존 코드 확인과 시야 계산을 반영해 수정). 상태: **계획만 작성**. 모델과 코드는 아직 바꾸지 않았습니다.

좌표: +X 앞, +Y 왼쪽, +Z 위, m. 각도는 정면 0°, 왼쪽 90°, 뒤 180°, 오른쪽 270°.

## 1. 목표와 범위

후진 진입과 후진 주행 때 로봇 뒤를 읽을 수 있는 센서 배치를 정합니다. v19 파일은 그대로 두고 `v20/`에서 작업합니다.

- **이번 범위:** v20 외형(센서 배치)과 시야·간섭 검사, Gazebo 모델에 외형 반영.
- **범위 밖:** `sim_lidar`와 주행 코드. 지금대로 씁니다 (7절).
- **라이다는 2D로 유지합니다.** 3D는 Gazebo 라이다 고장과 2D 지도 때문에 거의 새로 만들어야 합니다. 보고서의 향후 개선에 적습니다: "시뮬레이션은 2D 라이다를 가정했다. 실제 보도 주행에서는 연석·경사 인식을 위해 3D 라이다나 깊이 카메라를 추가해야 한다."

### 3.1 위치를 바꾼 이유

처음 제안한 B(−0.88, 0.49, 0.25)는 접힌 뒤 램프(x −0.98~−0.88, y ±0.42, z 0.14~0.46)의 높이 안에 있어 정후방이 가립니다.

## 4. 작업 순서

Blender 작업(1~6)은 **Mac**에서 합니다. 개발 VM에는 Blender가 없습니다.

1. **기준 측정:** 광선 검사를 `v20/scripts/fov_check_v20.py`로 만들고 v19 값을 기록합니다.
2. **모델 수정:** `v20/scripts/build_v20.py`에서 모서리 홈, 센서 메시, 후방 카메라와 브래킷을 추가합니다.
3. **파일 생성:** `scootover_v20.blend`와 `scootover_v20_anim.blend`를 **둘 다** 만듭니다. 애니메이션 파일이 없으면 팔 동작을 만들 수 없습니다.
4. **시야 검사:** 라이다 2개를 합친 가림과 카메라 시야를 계산합니다.
5. **간섭 검사:** 아래 자세 전체에서 겹침을 확인합니다.
   - 뒤 램프·지지대·앞 램프의 접힘과 펼침
   - 적재(1~729)와 하차(730~1690) 전 프레임
   - **카메라와 팔:** 카메라가 팔 어깨에서 약 13 cm라 우선 확인합니다.
6. **치수 여유 검사:** 폭 ±0.55, 로봇 충전소 출입구, 킥스팟 옆 슬롯 여유 2 cm.
7. **Gazebo 반영:** Mac에서 `export_gazebo.py` → VM에서 `build_blender_models.py` → 빌드 → `tools/update_legacy_hashes.py`.
8. **Gazebo 눈 확인:** 적재·하차, 그리고 **넘어진 킥보드 세우기** (이 팔 동작은 생성 스크립트가 만들어 Blender 간섭 검사에 포함되지 않음).
9. **사진·문서:** 센서 사진과 전후좌우 사진을 다시 렌더하고 "하드웨어 구성" 페이지를 고칩니다.

Mac을 쓸 수 없으면 `build_blender_models.py`에서 센서 모양만 덧붙일 수 있습니다 (모서리 홈 없음, 센서가 차체에 겹쳐 보일 수 있음).

## 7. ROS·Gazebo 영향

### 7.1 이번 작업
- Gazebo에서 바뀌는 것은 **외형뿐**이고 로봇 동작은 같습니다.
- 높은 라이다 외형을 지워도 `base_scan` 링크와 TF (0.86, 0, 1.04)는 남깁니다. `sim_lidar`와 주행 노드가 씁니다.
- **화면의 센서 배치와 스캔이 다릅니다.** 스캔은 계속 앞쪽 가상 라이다 하나에서 가림 없이 나옵니다. 발표 때 "센서 배치는 설계안, 시뮬레이션 스캔은 이상화"라고 밝힙니다.

### 7.2 나중에 할 경우 (별도 작업, 하루 이상 어림)
- 스캔은 합치지 말고 `/scan`, `/scan_rear`로 나눕니다. 원점이 다른 두 라이다를 합치면 가림 관계가 틀어집니다.
- `sim_lidar`: 센서 위치와 차체 가림 반영
- `nav_bridge`, `collector`, `mission_manager`, `extended_nav`: `/scan` 하나와 앞쪽 원점 하나를 가정한 부분 수정
- `sim_tag_detector`, `collector`: 후방 카메라 검출 추가, 후진 진입 때 사용
- 차체 길이 값(`footprint`, `UNDOCK_BODY_X0` 등)에 돌출분 반영

## 8. 위험

- 시야 계산은 **수송 자세만** 했습니다. 램프나 지지대를 펼친 상태는 확인하지 않았습니다. 램프 펼침과 지지대 펼침은 정차 중에만 해당합니다.
- 뒤로 튀어나온 라이다 B는 후진 때 가장 먼저 부딪히는 위치입니다.
- 후방 카메라와 팔의 간섭은 확인하지 않았습니다. 겹치면 카메라 높이나 위치를 바꾸고 시야를 다시 계산합니다.
- 0.25 m 높이의 2D 라이다는 낮은 연석을 놓치고, 경사로에서는 바닥을 장애물로 볼 수 있습니다.
- 팀의 하드웨어 설계 사항이므로 모델 담당과 정한 뒤 진행합니다.
